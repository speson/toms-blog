OpenAI의 코딩 에이전트 코덱스(Codex)는 이제 쓴 토큰 양만큼 크레딧을 깎는 방식으로 과금해요. 저는 그래서 플랜 이름보다 어떤 모델을 기본값으로 두느냐가 회사 비용을 더 크게 좌우한다고 봐요. 이 글에서는 Business와 Enterprise의 차이, 크레딧이 빠지는 구조, 도입 전에 걸어 둘 관리 설정을 한 번에 정리해요.

이 글의 가격과 요율은 2026년 9월 27일에 [공식 요금 문서](https://learn.chatgpt.com/codex/pricing)에서 다시 확인한 값이에요.

## Codex Business와 Enterprise는 무엇이 다른가요?

먼저 오해 하나를 풀고 갈게요. Codex는 Free부터 Enterprise까지 모든 ChatGPT 플랜에 들어 있어요. 그래서 "Codex를 쓰려면 Enterprise가 필요한가?"의 답은 "아니요"예요.

회사에서 실제로 고르는 건 Business와 Enterprise 둘 중 하나예요.

| 항목 | Business | Enterprise |
| --- | --- | --- |
| 가격 | 사용자당 월 $20 (연간 결제), 월 결제는 $25 | 영업 협의 |
| 최소 인원 | 2명 | 국내 리셀러 삼성SDS 안내 기준 150석, 연간 계약 |
| 좌석당 Codex 한도 | Plus와 같음 | 유연 과금이면 고정 한도 없이 크레딧만큼 사용 |
| 계정·권한 관리 | SAML SSO, MFA, 관리형 구성 | Business 기능 + SCIM, EKM, RBAC, 도메인 인증 |
| 데이터 | 업무 데이터 기본 학습 제외 | Business 기능 + 데이터 보존·저장 지역 통제 |
| 사용 현황 | 잔여 크레딧 확인, 사용량 리포트 다운로드 | 분석 대시보드, Analytics API, Compliance API·감사 로그 |

표의 용어를 풀면 이래요. SCIM은 사내 계정 시스템과 사용자 목록을 자동으로 맞추는 표준이에요. EKM은 고객이 암호화 키를 직접 관리하는 기능이고, RBAC는 역할별로 권한을 나누는 방식이에요.

Enterprise가 필요해지는 시점은 보통 인원보다 데이터 요건이 먼저 와요. 보존 기간, 저장 지역, 감사 로그가 필요하다면 Enterprise 영역이에요. 개발 조직만 쓴다면 Business와 워크스페이스 크레딧 조합으로 시작하는 게 무난해요.

참고로 크레딧으로만 과금되는 "Codex 전용 좌석"은 이제 새로 만들 수 없어요. 2026년 6월 24일 이전에 이 좌석을 추가한 Business 워크스페이스에만 남아 있어요.

## Codex 크레딧은 어떻게 빠지나요?

크레딧 과금은 세 단계로 움직여요.

1. <strong>좌석 포함 한도</strong>: 5시간 단위로 다시 채워지는 사용량이에요. Business 좌석은 Plus와 같은 한도를 받아요.
2. <strong>워크스페이스 크레딧</strong>: 포함 한도를 넘으면 회사가 산 공유 크레딧에서 빠져요.
3. <strong>모델별 요율</strong>: 100만 토큰당 몇 크레딧을 깎을지 모델마다 달라요.

Business 좌석 하나가 5시간 동안 보낼 수 있는 로컬 메시지 추정치는 아래와 같아요. 작업 크기에 따라 달라지는 추정치라 고정 한도는 아니에요.

| 모델 | 5시간당 로컬 메시지 (Business 추정) |
| --- | --- |
| GPT-6 Astra | 5–45 |
| GPT-6 Sol | 15–150 |
| GPT-6 Luna | 350–3,000 |
| GPT-5.6 Sol | 10–100 |
| GPT-5.6 Terra | 25–200 |
| GPT-5.6 Luna | 250–2,000 |

포함 한도를 넘은 뒤에는 아래 요율로 크레딧이 빠져요.

| 모델 | 입력 (100만 토큰당) | 출력 (100만 토큰당) |
| --- | --- | --- |
| GPT-6 Astra | 250 크레딧 | 1,250 크레딧 |
| GPT-6 Sol | 50 크레딧 | 250 크레딧 |
| GPT-6 Luna | 2.5 크레딧 | 12.5 크레딧 |
| GPT-5.6 Sol | 100 크레딧 (프로모션) | 500 크레딧 (프로모션) |
| GPT-5.6 Terra | 50 크레딧 | 300 크레딧 |
| GPT-5.6 Luna | 5 크레딧 | 30 크레딧 |

GPT-5.6 Sol의 요율은 프로모션 가격이에요. 공식 문서는 최소 2026년 11월 21일까지 유지된다고 적었어요. 이 프로모션은 구매한 크레딧에만 적용되고, 좌석 포함 한도는 그대로예요.

모델 선택이 비용을 얼마나 바꾸는지 계산해 보면 이래요. 같은 GPT-5.6 안에서 Sol은 Luna보다 입력 요율이 20배 비싸요. GPT-6 안에서는 Astra가 Luna의 100배예요. 이 글의 예전 판에는 "3~25배"와 "Sol 6~25배"가 섞여 있었는데, 요율표가 바뀌어서 지금 기준으로 다시 계산했어요.

빠른 모드(Fast mode)도 비용을 키워요. GPT-6 모델은 빠른 모드를 켜면 표준 요율의 2.5배가 빠져요.

크레딧을 운영할 때 챙길 건 세 가지예요.

- <strong>자동 충전 한도</strong>: Business 워크스페이스 소유자는 자동 충전(automatic recharge)을 켤 수 있어요. 켠다면 월 충전 한도와 사용량 알림부터 설정하세요. [에이전트 비용 사고](/posts/2026-07-21-agent-runaway-receipts)를 막는 최소 장치예요.
- <strong>유효 기간</strong>: Business 크레딧은 구매 후 12개월 동안 쓸 수 있어요. Enterprise는 계약서(Order Form)에 적힌 조건을 따라요.
- <strong>구매 단가</strong>: 크레딧 한 개의 달러 가격은 플랜과 계약에 따라 다르다고만 공개돼 있어요. 견적은 영업 담당자에게 받아야 해요.

API 키 방식도 있어요. 5시간 한도 없이 API 요금으로 내는 종량제예요. 대신 GitHub 코드 리뷰, Slack 연동 같은 클라우드 기능은 쓸 수 없어요. 그래서 CI(자동 빌드·테스트 파이프라인)는 API 키로, 개발자 좌석은 Business로 나누는 구성이 자연스러워요.

## 관리자는 Codex를 어떻게 통제하나요?

접근 통제의 출발점은 워크스페이스 설정이에요. "Allow members to use Codex and Work Locally" 권한으로 데스크톱 앱, CLI, IDE 확장 사용을 켜고 꺼요. 워크스페이스에 따라 Codex 로컬 권한이 따로 나뉘어 있기도 해요.

주의할 점이 하나 있어요. 워크스페이스에서 Codex를 켜도 GitHub 같은 연결 서비스의 권한은 따로예요. 소스 코드 접근은 그 서비스 쪽에서 다시 통제해야 해요.

기술 통제의 핵심은 관리형 구성 파일 `requirements.toml`이에요. 조직이 배포하면 개인 설정으로 덮어쓸 수 없는 규칙이 생겨요. 배포 위치는 Unix 계열이 `/etc/codex/requirements.toml`, Windows가 `%ProgramData%\OpenAI\Codex\requirements.toml`이에요.

조직이 강제할 수 있는 대표 항목은 이래요.

- 승인 정책과 권한 프로필 허용 목록 (`allowed_approval_policies`, Codex 0.138 이후는 `allowed_permission_profiles` 권장)
- 네트워크 도메인 규칙 (`[experimental_network]`, 아직 실험 기능이라 공식 문서도 전사 적용 전 검증을 권해요)
- 파일 읽기 차단 (예: `deny_read = ["/**/*.env", "~/.ssh"]`)
- Appshots(화면 캡처 첨부)와 원격 제어 끄기 (`allow_appshots = false`, `allow_remote_control = false`)

Business 이상에서는 클라우드에서 정책을 내려주는 방식도 쓸 수 있어요. 이 방식은 유효한 캐시 없이 정책을 받아오지 못하면 오류를 내요. 정책 없이 조용히 시작하지 않는다는 뜻이에요.

## Codex는 어떤 순서로 도입하나요?

공식 관리자 가이드는 담당자 지정부터 검증까지 여러 단계로 나눠 설명해요. 실무형으로 줄이면 네 단계예요.

1. <strong>파일럿 그룹</strong>: 소수 인원과 위험이 낮은 저장소로 시작해요.
2. <strong>표준화</strong>: 팀 규칙은 AGENTS.md(Codex가 읽는 프로젝트 규칙 파일)에 적어요. [메모리보다 AGENTS.md에 팀 규칙을 두는 이유](/posts/2026-07-28-codex-memory-image-guide)도 같은 맥락이에요.
3. <strong>통제 배포</strong>: `requirements.toml`, 크레딧 한도, 사용량 알림을 먼저 걸어요.
4. <strong>단계 확대</strong>: 도입률과 업무 지표를 보면서 그룹 단위로 넓혀요.

요점은 통제와 표준을 확대 전에 만드는 거예요.

국내에는 이미 큰 도입 사례가 있어요. OpenAI는 2026년 6월 21일 삼성전자에 ChatGPT Enterprise와 Codex를 공급한다고 발표했어요. 대상은 삼성전자 국내 전 임직원과 DX(디바이스경험) 부문 해외 임직원이에요.

조달 경로도 열려 있어요. 삼성SDS는 2025년 12월 국내 첫 OpenAI 리셀러 계약을 맺었어요. 국내 계약과 기술 지원이 필요하면 이 경로를 검토할 수 있어요.

좌석과 상위 제품은 구분해서 보면 좋아요. 좌석은 사람이 Codex를 쓰는 권리예요. [Frontier와 Presence는 에이전트를 만들고 배포하는 쪽의 제품](/posts/2026-07-27-openai-vertical-expansion)이에요. 직원이 Codex를 쓰는 게 목표라면 좌석으로 충분해요.

가격과 한도는 올해만 여러 번 바뀌었어요. 계약 전에는 공식 페이지에서 다시 확인하세요.

## 자주 묻는 질문

### Codex Business 플랜 가격은 얼마인가요?

연간 결제 기준 사용자당 월 $20이에요. 월 결제는 $25이고, 최소 2명부터 가입할 수 있어요 (2026년 9월 기준).

### Codex 크레딧은 이월되나요?

Business 크레딧은 구매 후 12개월 동안 쓸 수 있어요. Enterprise는 계약서에 적힌 조건을 따라요.

### Enterprise가 아니어도 requirements.toml을 쓸 수 있나요?

네. 공식 기능표에서 관리형 구성은 Business에서도 쓸 수 있어요. 다만 RBAC, SCIM, 감사 로그는 Enterprise 기능이에요.

### Codex에서 크레딧이 가장 적게 드는 모델은 무엇인가요?

요율표 기준으로는 GPT-6 Luna예요. 가벼운 반복 작업은 Luna로, 어려운 작업만 Sol이나 Astra로 올리는 구성이 비용을 아끼는 기본 방법이에요.
