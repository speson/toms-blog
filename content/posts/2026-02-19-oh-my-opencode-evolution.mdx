Oh My OpenCode(OMO)는 오픈소스 코딩 도구 OpenCode 위에서 여러 AI 에이전트를 나눠 일하게 하는 플러그인이에요. 저는 v3.0에서 v3.5까지 약 3주가 이 도구의 성격이 가장 크게 바뀐 시기라고 봐요. 이 글을 읽으면 버전별로 무엇이 달라졌는지, 지금 이름인 oh-my-openagent와 v5는 무엇인지 알 수 있어요.

> 2026년 10월 업데이트: 검색에서 'OpenCode 3'라고 부르는 건 대부분 이 글의 Oh My OpenCode v3예요. 공식 OpenCode 3은 아직 없고, OpenCode 1과 2의 차이는 [OpenCode 1과 2 차이와 업그레이드하는 법](/posts/2026-10-08-opencode-v1-v2-v3-difference)에 정리했어요.

이 글은 2월에 처음 썼고, 2026년 10월 11일에 깃허브 릴리스 노트로 다시 확인해 고쳤어요. 날짜는 한국 시간 기준이에요.

## Oh My OpenCode v3.0~v3.5는 버전별로 무엇이 다른가요?

| 날짜 | 버전 | 핵심 변화 |
| --- | --- | --- |
| 1/24 | v3.0.0 | 카테고리+스킬로 에이전트를 조합하는 구조, Prometheus·Atlas 추가 |
| 1/28 | v3.1.4 | 안정성 개선, 오류 알림 |
| 1/29 | v3.1.7 | MCP 서버용 OAuth 2.1 인증, LSP 클라이언트 교체 |
| 2/3 | v3.2.2 | GPT-5.2용 프롬프트 최적화 |
| 2/4 | v3.2.3 | 웹 검색 제공자 선택, 스킬 정리·끄기 |
| 2/11 | v3.5.0 | "Atlas Trusts No One" 결과 검증 강화, 645개 파일 리팩터링 |

약 3주 동안 6번 릴리스가 나왔어요.

## v3.0~v3.2에서는 무엇이 바뀌었나요?

### v3.0: 에이전트를 조합하는 방식

v3.0 전에는 "Git Master"처럼 역할이 고정된 에이전트를 썼어요. v3.0부터는 두 가지를 조합해요.

- <strong>카테고리</strong>: 어떤 모델을 쓸지 정하는 묶음 (quick, visual-engineering, ultrabrain, deep)
- <strong>스킬</strong>: 전문 지식 묶음 (frontend-ui-ux, git-master, playwright 등)

메인 에이전트인 Sisyphus가 작업에 맞게 둘을 골라 붙여요. 예를 들어 visual-engineering에 frontend-ui-ux를 붙이면 프론트엔드 담당이 돼요.

같은 버전에 에이전트 두 개도 들어왔어요. Prometheus는 사용자와 대화해 요구사항을 정리하고 작업 계획을 써요. Atlas는 그 계획을 받아 에이전트에게 일을 나누고 결과를 확인해요.

### v3.1~v3.2: 인증, 프롬프트, 편의 기능

v3.1.7에서는 MCP(AI 도구가 외부 서비스에 붙는 규격) 서버용 OAuth 2.1 인증이 들어왔어요. 관련 표준 4종(RFC 7591, 9728, 8414, 8707)을 지원해요. 같은 릴리스에서 LSP(편집기가 코드 오류를 알려 주는 규격) 클라이언트를 Microsoft의 vscode-jsonrpc 라이브러리로 바꿨어요.

v3.2.2에서는 Atlas, Sisyphus-Junior, Oracle에 GPT-5.2용 프롬프트가 들어왔어요. 어떤 모델을 쓰느냐에 따라 프롬프트 형식을 바꿔 주는 방식이에요.

v3.2.3에서는 쓰기 편해지는 변화가 모였어요.

- 웹 검색 제공자를 Exa(기본값)와 Tavily 중에서 고를 수 있어요.
- 스킬을 하위 폴더로 정리할 수 있어요.
- `disabledSkills` 설정으로 안 쓰는 스킬을 끌 수 있어요.

```json
{
  "disabledSkills": ["playwright", "dev-browser"]
}
```

## v3.5 "Atlas Trusts No One"은 무엇을 바꿨나요?

전에는 하위 에이전트가 "다 했다"고 하면 Atlas가 그대로 넘어갔어요. v3.5.0부터는 Atlas가 하위 에이전트가 고친 파일을 직접 읽고, 주장과 실제 코드를 대조해야 다음으로 넘어가요.

저는 이 변화가 v3에서 가장 중요하다고 봐요. AI 에이전트가 "완료"라고 했는데 절반만 된 문제를 도구 차원에서 막으려 한 거예요.

같은 릴리스에서 큰 리팩터링(동작은 그대로 두고 코드 구조를 정리하는 작업)도 했어요. 릴리스 노트 기준 수치는 이래요.

| 항목 | 수치 |
| --- | --- |
| 바뀐 파일 | 645개 |
| 줄 수 변화 | +34,507 / -21,492 |
| 파일당 상한 | 200줄 |

## 지금의 oh-my-openagent와 v5는 무엇인가요?

Oh My OpenCode는 지금 <strong>oh-my-openagent</strong>라는 이름의 저장소에서 개발돼요. 2026년 9월 27일(한국 시간)에 v5.0.0이 나왔고, 10월 초 기준 최신은 v5.1.x예요.

v5의 핵심은 <strong>OmO Native</strong>예요. OpenCode 플러그인이 아니라 `omo`라는 독립 명령으로 돌아가요. 릴리스 노트는 OpenCode용 플러그인과 Codex용 LazyCodex가 계속 동작하지만, 새 기능은 OmO Native에 먼저 들어간다고 밝혀요.

```bash
bun add -g omo-ai
omo setup
omo doctor
```

위 명령은 v5.0.0 릴리스 노트에 적힌 설치 절차예요. 제가 직접 실행해 확인하지는 않았어요. 저는 지금 새로 시작한다면 v3 기준 설명보다 v5 문서부터 보는 게 맞다고 봐요.

## 자주 묻는 질문

### Oh My OpenCode와 oh-my-openagent는 같은 건가요?

네. 같은 프로젝트가 이름을 바꿨어요. 깃허브의 예전 저장소 주소도 oh-my-openagent로 연결돼요.

### OpenCode 3이 Oh My OpenCode v3인가요?

검색에서 말하는 'OpenCode 3'는 대부분 Oh My OpenCode v3예요. 공식 OpenCode 3은 2026년 10월 기준 아직 없어요.

### v3 설정을 v5로 옮길 수 있나요?

v5.0.0 릴리스 노트는 `omo setup`이 API 키, MCP 서버, 스킬, 모델 선택을 옮겨 준다고 안내해요. OAuth 로그인은 다시 해야 해요.
