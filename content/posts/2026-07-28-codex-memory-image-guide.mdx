Codex에 메모리 기능이 있는데 왜 아무것도 기억을 못 할까요? 로컬 코덱스(Codex)의 메모리는 기본값이 꺼짐이라서 그래요. 저는 이 기본값 하나만 알아도 혼란의 절반은 풀린다고 봐요. 이 글을 읽으면 메모리 켜는 법, 꼭 알아야 할 설정, 이미지 생성이 거절될 때 대처법을 한 번에 챙길 수 있어요.

이 글은 2026년 10월 11일 기준 [공식 문서](https://learn.chatgpt.com/codex/customization/memories)를 다시 확인해 고친 판이에요. 처음 쓴 7월 판과 달라진 점은 글 끝에 적어 뒀어요.

## Codex 메모리는 어떻게 켜나요?

경로는 두 가지예요.

- <strong>앱에서</strong>: ChatGPT 데스크톱 → Settings → Personalization → <strong>Enable Codex memories</strong> 켜기
- <strong>설정 파일에서</strong>: `~/.codex/config.toml`에 아래 두 줄 추가

```toml
[features]
memories = true
```

앱 설정은 지금 쓰는 컴퓨터 한 대에만 적용돼요. 설정 파일 위치와 다른 키는 [config.toml 가이드](/posts/2026-09-28-codex-config-toml-guide)에 정리해 뒀어요.

켠 뒤에도 바로 기억하지는 않아요. Codex는 대화가 한동안 멈춘 뒤에 백그라운드에서 메모리를 만들어요. 아주 짧은 대화나 진행 중인 대화는 건너뛰어요. 남은 사용 한도가 기준보다 적을 때도 메모리 생성을 미뤄요.

대화 하나만 따로 정하고 싶으면 <strong>/memories</strong> 명령을 쓰면 돼요. 이 대화가 기존 메모리를 쓸지, 앞으로의 메모리 재료가 될지를 고를 수 있어요. 이 선택은 전체 설정을 바꾸지 않아요.

## 메모리와 AGENTS.md는 무엇이 다른가요?

Codex가 앞 작업을 이어 가는 방법은 세 가지예요.

| 방법 | 누가 쓰나 | 어디에 저장되나 | 용도 |
| --- | --- | --- | --- |
| 메모리 | Codex가 자동으로 | `~/.codex/memories/` (내 컴퓨터) | 개인 취향, 자주 하는 작업 |
| AGENTS.md | 사람이 직접 | 리포 안, 또는 `~/.codex/AGENTS.md` | 꼭 지켜야 할 팀 규칙 |
| codex resume | 사용자가 불러올 때 | 세션 기록 | 이전 대화 이어 하기 |

공식 문서도 꼭 지켜야 할 규칙은 AGENTS.md나 문서에 두라고 해요. 메모리는 도움이 되는 회상 도구로만 보라고 하고요. 메모리는 내 컴퓨터에만 있어서 팀원과 공유되지 않아요. 저도 팀 규칙을 메모리에만 두면 새 팀원 온보딩이 깨진다고 봐요.

ChatGPT 웹의 메모리와 로컬 Codex 메모리는 저장소가 서로 달라요. 웹 쪽 설정은 Codex 로컬 메모리에 영향을 주지 않아요.

## 메모리 설정은 무엇을 바꾸면 되나요?

자주 쓰는 키만 추리면 이래요. 모두 `config.toml`의 `[memories]` 아래에 써요.

| 키 | 하는 일 |
| --- | --- |
| `use_memories` | false면 기존 메모리를 새 세션에 넣지 않아요 |
| `generate_memories` | false면 새 대화를 메모리 재료로 쓰지 않아요 |
| `disable_on_external_context` | true면 MCP(외부 도구 연결 규격)·웹 검색을 쓴 대화를 메모리에서 빼요 |
| `min_rate_limit_remaining_percent` | 남은 한도가 이 비율보다 적으면 메모리 생성을 미뤄요 |

외부 웹 페이지나 도구 결과가 메모리에 섞이는 게 싫다면 `disable_on_external_context = true`를 권해요. 앱에서는 Allow memories from tool-assisted chats 설정이 같은 역할을 해요.

메모리를 지우려면 Settings → Personalization → <strong>Delete Codex memories</strong>를 누르면 돼요. 메모리 파일은 Codex가 만든 상태 파일이라, 손으로 고치는 걸 주된 관리 방법으로 삼지 말라고 문서에 적혀 있어요.

Codex는 메모리를 만들 때 시크릿(API 키 같은 비밀값)을 가려요. 그래도 Codex 홈 디렉터리를 남과 공유하기 전엔 파일을 직접 확인하세요. 내 대화가 OpenAI 모델 학습에 쓰이는지는 메모리와 별개 설정이에요. 이건 [Codex·ChatGPT 학습 끄는 법](/posts/2026-10-01-chatgpt-codex-data-training-off)에 따로 정리했어요.

## Codex 이미지 생성이 거절되면(검열) 어떻게 하나요?

먼저 기본 사용법이에요. Codex는 `gpt-image-2`로 이미지를 만들어요. 자연어로 부탁하거나 `$imagegen`을 프롬프트에 넣으면 돼요. 참고 이미지는 `-i` 옵션으로 붙여요.

```bash
codex '다크 모드 대시보드 헤더 배너 만들어줘 $imagegen'
codex -i screenshot.png "이 에러 설명하고 최소 수정안 제시해줘"
```

셸에서 큰따옴표를 쓰면 `$imagegen`이 빈 환경변수로 바뀌어 사라져요. 첫 줄처럼 작은따옴표로 감싸세요.

이미지 생성은 같은 일반 작업보다 사용 한도를 평균 3~5배 빨리 써요. 많이 만들 거라면 `OPENAI_API_KEY`를 설정해서 API 요금으로 돌리라고 공식 문서가 안내해요.

이제 '코덱스 검열'로 검색하신 분들이 겪는 상황이에요. 요청이 안전 필터에 걸리면 이미지가 안 나오고 거절 메시지가 떠요. 공식 문서가 조심하라고 짚는 영역은 세 가지예요.

| 거절되기 쉬운 요청 | 공식 문서 안내 | 바꿔 볼 표현 |
| --- | --- | --- |
| 실존 인물 묘사 | 허락받은 경우 참고 사진과 함께 | 가상의 인물로 바꾸기 |
| 특정 브랜드·작가·작품 흉내 | 독창적인 디자인을 요청하라 | "OO 스타일" 대신 색·구도·질감 묘사 |
| 정책 위반 소지 | OpenAI 사용 정책을 따르라 | 의도와 맥락을 구체적으로 적기 |

같은 프롬프트를 그대로 다시 보내면 대개 같은 결과가 나와요. 저는 재시도보다 표현을 바꾸는 게 빠르다고 봐요. 이미지 API의 `moderation` 값을 `low`로 내려도 필터 민감도만 낮아져요. 정책 위반 요청이 허용되지는 않아요.

## 자주 묻는 질문

### Codex 메모리를 켰는데 왜 바로 기억하지 않나요?

메모리는 대화가 한동안 멈춘 뒤 백그라운드에서 만들어져요. 짧은 대화는 건너뛰고, 남은 한도가 적으면 생성을 미뤄요.

### Codex 메모리는 어떻게 지우나요?

ChatGPT 데스크톱의 Settings → Personalization에서 Delete Codex memories를 누르면 돼요. 지금 쓰는 컴퓨터의 메모리만 지워져요.

### Codex 이미지 생성은 무료인가요?

요금제에 포함된 Codex 사용 한도에서 차감돼요. 일반 작업보다 평균 3~5배 빨리 줄어요.

### 팀에서 이미지 생성을 막을 수 있나요?

네. `config.toml`에서 `imagegen` 기능을 끌 수 있어요. 정확한 키는 [config.toml 가이드](/posts/2026-09-28-codex-config-toml-guide)를 보세요.

### 7월 판에서 무엇이 바뀌었나요?

메모리 삭제 버튼(Delete Codex memories)이 공식 문서에 생겨서, "초기화 방법이 없다"는 예전 설명을 고쳤어요. 문서에서 빠진 `max_unused_days` 키와 서드파티 출처의 이미지 제약(투명 배경, 해상도)은 뺐어요.
