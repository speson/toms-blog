ChatGPT나 Codex에 평범한 부탁을 했는데 "도와줄 수 없다"는 답이 돌아올 때가 있어요. 저는 이 비슷한 문구 뒤에 서로 다른 원인이 여럿 섞여 있어서, 원인을 모른 채 문장만 고치면 시간만 버린다고 봐요. 이 글을 읽으면 내 거절이 어디서 왔는지 가려내는 법과 원인별로 정당하게 푸는 방법을 알 수 있어요.

결론부터 표로 정리할게요 (2026년 10월 기준).

| 이렇게 보이면 | 원인 | 먼저 할 일 |
| --- | --- | --- |
| 일부만 거절하고 대안을 제시함 | 모델 정책 | 대안 범위로 이어 가거나 목적을 밝히기 |
| 응답이 늦어지다가 내용이 안 나옴 | 추가 안전 검사 | 방어·예방 목적으로 범위 좁히기 |
| Codex가 실행 전에 멈추고 승인을 물음 | 샌드박스·승인 설정 | `/permissions`나 `config.toml` 확인 |
| 경고와 함께 응답이 제한되거나 작업이 멈춤 | Codex 사이버 안전장치·안전 모니터링 | 알림 확인, 오탐이면 `/feedback` |
| "Something went wrong" 같은 오류 | 기술 오류 (거절 아님) | 새로고침, 상태 페이지 확인 |

마지막 줄은 거절이 아니에요. 오류 문구는 [ChatGPT 오류 해결 문서](https://help.openai.com/en/articles/7996703-troubleshooting-chatgpt-error-messages)대로 새로고침이나 VPN 끄기부터 해 보면 돼요. 아래에서는 나머지 넷을 차례로 볼게요.

## ChatGPT는 왜 멀쩡한 질문을 거절하나요?

OpenAI가 모델 행동 기준으로 공개하는 문서가 <strong>모델 스펙(Model Spec)</strong>이에요. 2026년 8월 18일 판은 의도가 불분명하면 <strong>선의를 가정하고 답하라</strong>고 적어요.

반대로 대화 맥락에서 나쁜 의도가 읽히면 거절하라고 해요. 같은 정보라도 다른 맥락이면 답했을 내용까지요 ([Model Spec](https://model-spec.openai.com/2026-08-18.html)). 그래서 앞선 대화나 거친 표현 때문에 평범한 질문이 막히는 일이 생겨요.

GPT-5부터는 <strong>세이프 컴플리션(safe completion, 위험한 부분만 빼고 나머지는 최대한 답하는 방식)</strong>을 써요. 예전처럼 전부 답하거나 전부 거절하는 대신, 안전한 범위를 골라 답해요 ([OpenAI 설명](https://openai.com/index/gpt-5-safe-completions/)). OpenAI도 2026년 3월 GPT-5.3 Instant를 내면서 불필요한 거절을 줄였다고 밝혔어요 ([GPT-5.3 Instant](https://openai.com/index/gpt-5-3-instant/)).

정당한 질문이 막혔다면 이렇게 다시 물어보면 돼요.

1. <strong>새 채팅</strong>을 열어 앞선 대화의 영향을 없애요.
2. 첫 문장에 <strong>목적과 상황</strong>을 적어요. 예: "우리 회사 서버 로그에서 침입 흔적을 찾으려고 해요."
3. 원하는 결과를 <strong>원리·점검 목록·방어 방법</strong>처럼 좁혀요.
4. 답변이 대안을 줬다면 그 범위 안에서 이어 가요.

여기서 주의할 점이 있어요. 같은 내용을 말투만 바꿔 다시 묻는 건 효과가 없어요. OpenAI 헬프 문서도 표현을 바꾼다고 허용 여부가 바뀌지는 않는다고 적어요. 저는 목적을 정직하게 밝히는 게 가장 빠른 길이라고 봐요.

## '추가 안전 검사' 뒤에 답이 안 나오면 어떻게 하나요?

사이버 보안이나 생물학 관련 요청에는 <strong>추가 자동 안전 검사</strong>가 붙을 수 있어요. ChatGPT, Codex, API 모두 해당해요.

검사 중에는 응답이 평소보다 늦어요. 안전하게 답할 수 있으면 그대로 이어지고, 아니면 내용이 표시되지 않아요. 이 안내가 떴다고 해서 <strong>정책 위반으로 판정된 건 아니에요</strong> ([추가 안전 검사 헬프](https://help.openai.com/en/articles/20001326-additional-safety-checks-for-biological-and-cybersecurity-requests-in-chatgpt-codex-and-the-api)).

헬프 문서가 권하는 대처는 이래요.

- [이용 정책(Usage Policies)](https://openai.com/policies/usage-policies/)에 맞는 요청인지 먼저 확인해요.
- 보안 작업이면 <strong>찾기·막기·고치기</strong> 같은 방어 결과에 초점을 맞춰요. 목적에 필요 없는 공격 세부는 빼요.
- 생물학 작업이면 안전·예방·위험 분석에 초점을 맞추고, 필요 없는 실험 절차는 빼요.

회사 일로 허가받은 보안 점검을 한다면 <strong>Daybreak</strong>라는 별도 프로그램이 있어요. OpenAI의 신뢰 접근(Trusted Access for Cyber) 프로그램 이름이에요. 기본 등급인 Daybreak Blue는 방어 작업에서 거절을 줄여 줘요.

개인이 신청하려면 만 18세 이상이어야 해요. 유료 요금제와 고급 계정 보안(Advanced Account Security)도 필요해요. 여기에 FIDO2 하드웨어 보안 키가 하나 이상 있어야 해요 ([Daybreak 개요](https://help.openai.com/en/articles/20001258-openai-daybreak-trusted-access-for-cyber-overview), [자주 생기는 문제](https://help.openai.com/en/articles/20001259-openai-daybreak-common-issues-and-troubleshooting)). 승인은 자동이 아니고, 승인돼도 모든 안전장치가 풀리지는 않아요.

정당한 요청이 계속 막히면 오탐(false positive, 문제없는 요청을 위험하다고 잘못 판단한 것)으로 신고해요. 답변의 싫어요 버튼을 누르고, 반복되면 OpenAI 지원팀에 아래를 보내면 돼요.

- 받은 안전 안내 문구 그대로
- 쓴 모델과 서비스 (ChatGPT, Codex, API 중 어디인지)
- 날짜, 시간, 시간대
- 요청 ID (있으면)
- 민감 정보를 지운 짧은 작업 설명

비밀번호나 인증 코드, 회사 기밀은 넣지 말라고 문서에 적혀 있어요.

## Codex가 명령을 안 돌리거나 작업이 멈추는 건 왜인가요?

Codex에서 "못 한다"는 상황은 거절보다 <strong>권한 설정</strong> 때문인 경우가 많아요. 로컬 Codex는 운영체제 수준의 <strong>샌드박스(sandbox, 프로그램이 건드릴 수 있는 범위를 제한하는 장치)</strong> 안에서 명령을 돌려요.

기본값은 이래요 ([승인과 보안 문서](https://developers.openai.com/codex/agent-approvals-security)).

| 항목 | 기본 동작 |
| --- | --- |
| 네트워크 | 꺼져 있음 |
| 파일 쓰기 | 현재 작업 폴더 안에서만 |
| 작업 폴더 밖 수정, 네트워크 명령 | 실행 전에 승인을 물음 |
| Git 저장소가 아닌 폴더 | 읽기 전용 모드를 권장 |
| `.git`, `.codex` 폴더 | 작업 폴더 안이어도 읽기 전용 |

그래서 "패키지 설치가 안 된다"거나 "커밋을 못 한다"는 건 대부분 이 설정 때문이에요. 확인 순서는 이래요.

1. `/status`로 지금 작업 폴더 범위를 봐요.
2. `/permissions`로 읽기 전용인지, 쓰기 가능 모드인지 바꿔요.
3. 명령에 네트워크가 꼭 필요하면 `~/.codex/config.toml`에 아래 설정을 넣어요.

```toml
[sandbox_workspace_write]
network_access = true
```

이 설정은 공식 문서 예시 그대로 옮긴 거예요. 파일 위치와 다른 키는 [Codex config.toml 가이드](/posts/2026-09-28-codex-config-toml-guide)에 정리해 두었어요.

샌드박스와 승인을 통째로 끄는 `--yolo` 옵션도 있어요. 공식 문서도 권하지 않는 설정이에요. 저는 필요한 권한만 하나씩 여는 쪽이 맞다고 봐요.

권한 문제가 아닌데 막힌다면 <strong>사이버 보안 안전장치</strong>일 수 있어요. GPT-5.3-Codex 이후 모델은 사이버 능력이 높은 등급으로 분류돼요. 그래서 비밀번호 탈취처럼 명백히 악의적인 요청은 거절하도록 학습돼 있어요. 자동 감시가 요청을 막거나 다른 모델로 넘기거나 제한할 수도 있어요 ([Codex 사이버 안전 문서](https://developers.openai.com/codex/concepts/cyber-safety)).

이 감시는 오탐도 내요. 2026년 2월에는 평범한 기능 개발 요청이 다른 모델로 넘어갔다는 버그 리포트가 여럿 올라왔어요 ([GitHub 이슈](https://github.com/openai/codex/issues/12060)). 이럴 땐 화면 알림을 확인하고, Codex에서 `/feedback`을 실행해 Safety Check 항목으로 신고하면 돼요.

마지막으로 GPT-6 Astra에는 <strong>안전 모니터링</strong>이 붙어 있어요. 작업 중 위험한 모델 행동을 감지하면 작업을 일시정지해요. 앱에서는 감지 내용을 확인한 뒤 이어서 할 수 있어요. Codex CLI와 모바일에서는 감지 내용과 재개 기능이 없어서 작업이 그대로 끝나요.

## 자주 묻는 질문

### 탈옥 프롬프트를 쓰면 풀리지 않나요?

권하지 않아요. OpenAI [이용약관](https://openai.com/policies/row-terms-of-use/)은 안전장치를 우회하는 행위를 금지해요. 정당한 요청이라면 목적과 범위를 밝히고, 그래도 막히면 오탐 신고를 하는 게 맞아요.

### 요금제를 올리면 거절이 줄어드나요?

요금제를 올린다고 정책 기준이 바뀌지는 않아요. 예외는 보안 작업용 Daybreak인데, 이것도 유료 요금제에 더해 별도 승인이 필요해요.

### 추가 안전 검사 안내가 떴다면 위반 판정을 받은 건가요?

아니요. 헬프 문서는 안내가 떴다는 것만으로 위반이 확정된 건 아니라고 적어요. 같은 요청이 반복해서 막힐 때만 지원팀에 문의하면 돼요.

### Codex 승인 창이 너무 자주 떠요. 줄일 수 있나요?

`config.toml`에 `approvals_reviewer = "auto_review"`를 넣으면 승인 요청을 검토 에이전트가 먼저 판단해요. 검토에 모델 호출이 더 들어가서 Codex 사용량이 늘 수 있어요.
