# /publish

선택된 뉴스 항목을 MDX 포스트로 발행

## 콘텐츠 모델 (가장 중요)

이 커맨드는 `.claude/content-model.md`와 `.claude/guides/writing-style.md`를 **반드시** 따릅니다.
글을 쓸 때는 writing-style의 **"0. 독자 우선"(R1–R10 + SEO 규칙)** 을 가장 먼저 적용합니다:

- 뉴스 1건 번역·요약 금지 → Tom 시각의 창작 칼럼 (Google Ads 품질)
- 제목: 독자가 얻는 것을 보여주는 문장. 날짜로 시작 금지, 영어 용어 1개 이하, 핵심 검색어는 앞 30자 안에 (R1·SEO)
- 도입 3문장: 쉬운 말로 무슨 일 → 왜 중요(내 판단) → 독자가 얻는 것. 날짜·숫자로 시작 금지 (R2)
- 문장당 새 정보 1개, ~60자, 숫자 2개 이하, · 나열 3항목 이하 (R3). 용어는 첫 등장에 괄호 풀이 (R4)
- 질문 하나, 핵심 숫자 5개 이하, H2 3–4개. 숫자가 많으면 표로 (R9). "남는 문장" 헤딩 금지. 엔딩은 `근거가 된 소식:`
- 가독성 기준 글: `2026-07-28-codex-memory-image-guide` / 칼럼 논증 참고: `2026-08-10-apple-openai-lawsuit`

핵심 원칙:

> 글의 단위는 "기사"가 아니라 "내 관점"이다. 뉴스 1건을 그대로 번역·요약하지 마세요.
> 출처는 근거·인용이고, 글의 척추는 Tom의 주장·해석입니다. (2차 가공 금지)

기본 모델: 관점/주장 칼럼 · 종합 다이제스트 · 비교/평가 프레임워크.

## 실행 단계

1. `.claude/news/` 디렉토리에서 가장 최근 뉴스 파일 찾기
2. 선택 읽기 — 두 단계로:
   - 먼저 `## 글 후보 (각도 제안)` 섹션에서 `[x]`된 후보를 읽는다 (`/fetch-news`가 묶어 둔 것).
     후보의 각도·재료(#번호)·허브 링크·"확인 필요"가 3단계의 출발점이다.
   - 후보가 하나도 체크되지 않았으면 `## 수집 항목`의 개별 `[x]` 항목으로 폴백한다
     (이때는 3단계에서 각도를 처음부터 세운다).
   - 선택된 재료의 원문을 정독한다 (사실 근거 확보). 후보의 "확인 필요"는 여기서 반드시 검증한다.
3. **각도 잡기 (angle-first — 절대 건너뛰지 말 것)**:
   - 선택 항목을 1:1로 요약하지 않는다. 후보의 한 줄 각도를 원문 정독 결과로 다듬거나,
     폴백이면 이들을 관통하는 **한 줄 주장/질문**을 새로 세운다. 후보 각도를 그대로 확정하지 않는다.
   - 위키(`content/wiki/`)에서 관련 맥락·이전 글을 읽어 연결고리를 찾는다.
   - 티어 판단: 대형 단독 사건만 단독 글(단, "발표 내용"이 아니라 "그래서 왜 중요한가"가 척추) /
     연결되는 2~4건은 하나의 칼럼·다이제스트로 묶음 / 사소한 패치는 다이제스트·생략.
   - 사용자에게 **발행 계획(각도)** 을 먼저 제시하고 확인받는다:
     ```
     발행 계획 (N개 글):
     1. [칼럼] "주장 한 줄" ← 근거: 항목 #x,#y + 내부링크 [기존글]
     2. [다이제스트] "흐름 한 줄" ← 항목 #a,#b,#c 묶음
     이대로 쓸까요? 각도를 바꾸고 싶으면 말씀해 주세요.
     ```
4. 확인 후 각 글 작성 (`.claude/content-model.md`의 가치 테스트 통과 필수):
   - 첫 문단은 도입 3문장(무슨 일 / 왜 중요 / 무엇을 얻나). 출처 소개로 시작하지 않는다.
   - 출처는 근거로 인용하고 출처명·링크를 명시. 내부링크는 개념 설명용일 때만, 본문 최대 3개 (R7).
   - 가짜 경험("제가 써보니") 날조 금지, 일반론 총평("추천합니다") 금지.
   - 날짜·가격이 들어가면 기준 시점("(2026년 9월 기준)")을 적고, 가격은 공식 가격표로 다시 확인한다.
   - 발행 전에 writing-style 체크리스트를 돈다. 특히 "이 분야를 모르는 개발자가 도입 3문장만 읽고
     무슨 글인지 말할 수 있는가?"와 "소리 내어 읽을 때 숨이 막히는 문장이 없는가?"
   - MDX 생성 (`content/posts/YYYY-MM-DD-slug.mdx`)
   - 썸네일 생성 (실패 시 `thumbnail` 필드 생략, OG 폴백):
     `generateThumbnail({ title, description, slug, tags })`
5. 생성된 포스트 목록 표시
6. **위키 업데이트** (자동):
   - `content/wiki/index.md` 읽어서 전체 위키 구조 파악
   - 새 포스트의 태그/소스/주제와 관련된 엔티티/토픽 위키 페이지 식별
   - 관련 위키 페이지 업데이트:
     - 엔티티 페이지: 타임라인에 새 항목 추가, `last_covered` 날짜 갱신, `post_count` 증가
     - 토픽 페이지: 관련 포스트 테이블에 추가, 핵심 포인트에 새 인사이트 반영
   - 기존 위키에 없는 새로운 엔티티/토픽이 감지되면:
     - 사용자에게 새 위키 페이지 생성 여부 확인
     - 승인 시 새 페이지 생성 + index.md에 추가
   - `content/wiki/log.md`에 인제스트 기록 추가:
     - 형식: `## [YYYY-MM-DD] ingest | [포스트 제목]`
     - 업데이트된 위키 페이지 목록
   - `content/wiki/index.md`의 포스트 수 갱신

## 글쓰기 스타일

모든 포스트는 `.claude/guides/writing-style.md`의 Tom 스타일 가이드를 따릅니다.
맨 앞의 "0. 독자 우선"(R1–R10 + SEO)이 아래 모든 항목보다 우선합니다:

- 독자 우선 요약: 문장형 제목(R1) · 도입 3문장(R2) · 문장당 정보 1개(R3) · 용어 풀이(R4) · 은유 글당 1개(R5) ·
  작업실 용어(척추·각도·곁가지·훅·층·칸·옆 메모) 본문 금지(R6) · 내부링크 최대 3개, "X 글이 A였다면 오늘은 B" 금지(R7) ·
  tldrVerdict 2문장 150자(R8) · 질문 하나/숫자 5개/H2 3–4개(R9) · 해요체 통일, "~로 읽혀요" 1회 이하(R10)
- 고정 인사말 금지: "안녕하세요, Tom입니다."로 시작하지 않는다. 첫 문장은 글마다 다르게, 주장/질문으로 시작
- 해요체로 통일: "~입니다/합니다"를 섞지 않는다 (R10)
- 경험 주장은 실제로 한 것만: 사용해보지 않은 것에 "제가 써본 결과" 같은 표현 금지. 의견은 의견으로("~라고 생각해요", "~로 보여요")
- 사고 구조 먼저 선택 (v3, 가장 중요): 글쓰기 전에 이 글의 사고 구조를 하나 고른다 (시간순 추적 / 반박·검증 Q&A / 단일 질문 파기 / 비교 프레임 / 인터뷰 재구성 / 짧은 단평). 직전 2편과 같은 구조 금지. 그 구조가 헤딩·순서·마무리를 결정 — 상세는 .claude/guides/writing-style.md 3-1절
- 새로 굳은 서명 차단: "검증 가능한 관전 포인트를 남길게요", "만약 X라면 Y할 거예요", "한 문장으로 정확히 옮기면", "한 줄로 줄이면" 마무리 전부 금지. 예측은 본문 논증에 녹인다
- "A가 아니라 B" 재프레이밍은 글당 1회 이하 (가장 깊은 지문). 한국 관점을 끝에서 두 번째 고정 섹션으로 두지 않는다. 고정 헤딩("이렇게 볼 수도 있어요"·"한국 개발자 입장에서") 은퇴. 은유는 글당 1개, 첫 등장에 뜻을 적는다 (R5)
- 핵심 판단은 "저는 ~라고 봐요"로 드러내되 글당 2~3회 이내 (R10), 대시(—) 콜론 대용 남용 금지
- 새로 굳은 서명 은퇴(2026-08): 열거형 한국 마무리("N가지가 실무적이에요. 하나… 둘…"), 자기반영 메타("이 블로그도…") 마무리 공식, "A가 아니라 B"의 헤딩 침투 금지 — 상세는 .claude/guides/writing-style.md 3-3절. 공통 감정 곡선 자체를 깰 것(배치마다 제약 하나씩 바꾸기)
- 이모지 절대 금지: 본문/헤딩/리스트 어디에도 이모지를 넣지 않음
- 팁/주의는 평문으로: "팁:", "주의:", "참고:" 같은 텍스트로 명시

## 이모지 금지 규칙 (필수)

포스트 본문, 헤딩, 리스트 어디에도 이모지를 절대 넣지 마세요.

- 금지: 💡 🎯 ⚠️ ✅ ❌ 🤔 💰 🚀 🔍 📝 🛠 🤖 ⚡ 🌐 (그 외 모든 이모지)

## MDX 포스트 형식 (thesis-first 칼럼 기본형)

> 아래는 "관점/주장 칼럼"의 기본 골격입니다. 출처의 구조를 따라가지 말고 내 논증을 따라갑니다.
> 다이제스트/비교 모델은 `.claude/content-model.md`의 각 모델 구조를 참고하세요.

```mdx
---
title: "[독자가 얻는 것을 보여주는 문장 — 실제 검색어, 핵심 키워드는 앞 30자 안]" # 날짜로 시작 금지, 영어 용어 1개 이하 (R1)
description: "[내 관점이 담긴 2-3문장. 무엇을 다루고 독자가 무엇을 얻는지]"
tldrVerdict: "[내 판단 2문장, 150자 이내, 숫자 2개 이하]" # description·첫 문단 문장 반복 금지 (R8)
date: "YYYY-MM-DD"
tags: ["적절한태그1", "적절한태그2"] # 3글 이상 모일 구체적 태그만. 범용 "AI" 태그 금지
category: "ai-news" # ai-news | by-tom
subcategory: "column" # 칼럼/분석=column, 단순소식=news, 릴리스=releases
source: "anthropic" # 트리거 출처(anthropic|openai|google|xai|deepseek|kimi|glm|geeknews|github), 자체기획=original
sourceUrl: "https://..." # 트리거 출처 URL (자체기획이면 빈 값)
thumbnail: "/thumbnails/{slug}.png" # 생성 실패 시 생략
draft: false
---

[도입 3문장 (R2). 고정 인사말·출처 소개·날짜/숫자 없이 시작.
1) 무슨 일이 있었나 — 쉬운 말로
2) 왜 중요한가 — "저는 ~라고 봐요"
3) 이 글을 읽으면 무엇을 얻나
질문으로 열면 다음 문장에서 바로 답한다. 문장 모양은 글마다 다르게.]

## [검색하듯 묻는 질문형 H2 — 예: "Codex 메모리는 왜 기본으로 꺼져 있나요?"]

[Anthropic 발표에 따르면](출처URL) [핵심 사실]이에요. 문장 하나에 새 정보 하나.
용어는 첫 등장에 괄호로 풀이 (R4). 숫자가 여러 개면 문장 대신 표로 (R9).

## [질문형 H2 — 내 판단: 이게 무엇을 의미하나]

[사실의 재서술이 아니라 내 판단. "저는 ~라고 봐요". 개념 설명이 필요하면 [기존 글](/posts/slug) 링크 (최대 3개, R7).]

[반론·한국 관점은 고정 헤딩 없이 본문에 필요할 때만. writing-style 3-1 준수.]

## 자주 묻는 질문

### [검색어 형태의 질문 1]

[1–3문장 답. 날짜·가격이면 "(2026년 9월 기준)"처럼 기준 시점.]

### [질문 2]

[1–3문장 답.]

---

근거가 된 소식: [출처1 제목](URL), [출처2 제목](URL)
```

### frontmatter 작성 규칙

- `title`: 독자가 얻는 것이 보이는 문장. 날짜로 시작 금지, 영어 용어 1개 이하, 핵심 검색어는 앞 30자 안 (R1·SEO).
  영어 제품명은 한국어와 함께 ("클로드 코드(Claude Code)").
- `description`: 2–3문장. 무엇을 다루고 독자가 무엇을 얻는지.
- `tldrVerdict`: <strong>2문장, 150자 이내, 숫자 최대 2개</strong>. description이나 첫 문단 문장을 되풀이하지 않고
  "그래서 나는 어떻게 판단하나"만 담는다 (R8).
- 가격·날짜가 핵심인 글은 `updatedAt`을 넣고, 본문에 기준 시점을 적는다.

## 위키 업데이트 규칙

- 위키 페이지는 `content/wiki/` 디렉토리에 위치
- 엔티티 페이지 (`entities/`): 기업, 제품, 서비스별 페이지
- 토픽 페이지 (`topics/`): 기술 트렌드, 개념별 페이지
- 새 포스트 발행 시 반드시 관련 위키 페이지를 업데이트할 것
- 위키 내용은 블로그에서 실제 다룬 내용만 기록 (추측/외부 정보 X)
- 교차참조: 관련 엔티티/토픽 간 `[[링크]]` 유지
