# /publish

선택된 뉴스 항목을 MDX 포스트로 발행

## 콘텐츠 모델 (가장 중요)

이 커맨드는 `.claude/content-model.md`를 **반드시** 따릅니다. 핵심 원칙:

> 글의 단위는 "기사"가 아니라 "내 관점"이다. 뉴스 1건을 그대로 번역·요약하지 마세요.
> 출처는 근거·인용이고, 글의 척추는 Tom의 주장·해석입니다. (2차 가공 금지)

기본 모델: 관점/주장 칼럼 · 종합 다이제스트 · 비교/평가 프레임워크.

## 실행 단계

1. `.claude/news/` 디렉토리에서 가장 최근 뉴스 파일 찾기
2. `[x]` 체크된 항목 파싱 + 각 항목 원문 fetch (사실 근거 확보)
3. **각도 잡기 (angle-first — 절대 건너뛰지 말 것)**:
   - 선택 항목을 1:1로 요약하지 않는다. 먼저 이들을 관통하는 **한 줄 주장/질문**을 세운다.
   - 위키(`content/wiki/`)에서 관련 맥락·이전 글을 읽어 연결고리를 찾는다.
   - 티어 판단: 대형 단독 사건만 단독 글(단, "발표 내용"이 아니라 "그래서 왜 중요한가"가 척추) /
     연결되는 2~4건은 하나의 칼럼·다이제스트로 묶음 / 사소한 패치는 다이제스트·생략.
   - 사용자에게 **발행 계획(각도)** 을 먼저 제시하고 확인받는다:
     ```
     발행 계획 (N개 글):
     1. [칼럼] "주장 한 줄" ← 근거: 항목 #x,#y + 내부링크 [기존글]
     2. [다이제스트] "흐름 한 줄" ← 항목 #a,#b,#c 묶음
     이대로 쓸까요? 각도를 바꾸고 싶으면 말씀해 주세요.
     ```
4. 확인 후 각 글 작성 (`.claude/content-model.md`의 가치 테스트 통과 필수):
   - 첫 문장부터 내 주장/질문이 보이게. 출처 소개로 시작하지 않는다.
   - 출처는 근거로 인용하고 출처명·링크를 명시. 본문에 기존 블로그 글 내부링크 1개 이상.
   - 가짜 경험("제가 써보니") 날조 금지, 일반론 총평("추천합니다") 금지.
   - "한국 개발자에게 이게 왜 중요한가" 한 단락 (의견으로, 사실 날조 없이).
   - MDX 생성 (`content/posts/YYYY-MM-DD-slug.mdx`)
   - 썸네일 생성 (실패 시 `thumbnail` 필드 생략, OG 폴백):
     `generateThumbnail({ title, description, slug, tags })`
5. 생성된 포스트 목록 표시
6. **위키 업데이트** (자동):
   - `content/wiki/index.md` 읽어서 전체 위키 구조 파악
   - 새 포스트의 태그/소스/주제와 관련된 엔티티/토픽 위키 페이지 식별
   - 관련 위키 페이지 업데이트:
     - 엔티티 페이지: 타임라인에 새 항목 추가, `last_covered` 날짜 갱신, `post_count` 증가
     - 토픽 페이지: 관련 포스트 테이블에 추가, 핵심 포인트에 새 인사이트 반영
   - 기존 위키에 없는 새로운 엔티티/토픽이 감지되면:
     - 사용자에게 새 위키 페이지 생성 여부 확인
     - 승인 시 새 페이지 생성 + index.md에 추가
   - `content/wiki/log.md`에 인제스트 기록 추가:
     - 형식: `## [YYYY-MM-DD] ingest | [포스트 제목]`
     - 업데이트된 위키 페이지 목록
   - `content/wiki/index.md`의 포스트 수 갱신

## 글쓰기 스타일

모든 포스트는 `.claude/writing-style.md`의 Tom 스타일 가이드를 따릅니다:

- 고정 인사말 금지: "안녕하세요, Tom입니다."로 시작하지 않는다. 첫 문장은 글마다 다르게, 주장/질문으로 시작
- 대화체 한국어 사용: "~입니다" 대신 "~예요/해요"
- 경험 주장은 실제로 한 것만: 사용해보지 않은 것에 "제가 써본 결과" 같은 표현 금지. 의견은 의견으로("~라고 생각해요", "~로 보여요")
- 사고 구조 먼저 선택 (v3, 가장 중요): 글쓰기 전에 이 글의 사고 구조를 하나 고른다 (시간순 추적 / 반박·검증 Q&A / 단일 질문 파기 / 비교 프레임 / 인터뷰 재구성 / 짧은 단평). 직전 2편과 같은 구조 금지. 그 구조가 헤딩·순서·마무리를 결정 — 상세는 .claude/writing-style.md 3-1절
- 새로 굳은 서명 차단: "검증 가능한 관전 포인트를 남길게요", "만약 X라면 Y할 거예요", "한 문장으로 정확히 옮기면", "한 줄로 줄이면" 마무리 전부 금지. 예측은 본문 논증에 녹인다
- "A가 아니라 B" 재프레이밍을 매 글 쓰지 않는다 (가장 깊은 지문). 한국 관점을 끝에서 두 번째 고정 섹션으로 두지 않는다. 고정 헤딩("이렇게 볼 수도 있어요"·"한국 개발자 입장에서") 은퇴. 재활용 은유(문법/실물/청구서/옷/화폐/축) 금지
- "저는 ~라고 봐요" 1인칭 의견 표지 글당 1~2회, 대시(—) 콜론 대용 남용 금지
- 이모지 절대 금지: 본문/헤딩/리스트 어디에도 이모지를 넣지 않음
- 팁/주의는 평문으로: "팁:", "주의:", "참고:" 같은 텍스트로 명시

## 이모지 금지 규칙 (필수)

포스트 본문, 헤딩, 리스트 어디에도 이모지를 절대 넣지 마세요.

- 금지: 💡 🎯 ⚠️ ✅ ❌ 🤔 💰 🚀 🔍 📝 🛠 🤖 ⚡ 🌐 (그 외 모든 이모지)
- 대신 평문으로: "팁:", "주의:", "참고:", "핵심:" 같은 텍스트 사용

이모지는 AI가 쓴 느낌을 주는 가장 큰 원인이에요. 반드시 제거하세요.

## 볼드 처리 규칙 (필수)

`**text**` 구조는 절대 사용하지 마세요. 한국어에서는 MDX 파서가 제대로 치환하지 못하는 경우가 많아요.

볼드가 필요하면 반드시 `<strong>text</strong>` HTML 태그를 사용하세요.

- ❌ `**핵심 기능**`
- ✅ `<strong>핵심 기능</strong>`

## MDX 포스트 형식 (thesis-first 칼럼 기본형)

> 아래는 "관점/주장 칼럼"의 기본 골격입니다. 출처의 구조를 따라가지 말고 내 논증을 따라갑니다.
> 다이제스트/비교 모델은 `.claude/content-model.md`의 각 모델 구조를 참고하세요.

```mdx
---
title: "[주장·질문이 드러나는 제목] — [핵심 한 줄]"
description: "[내 관점이 담긴 2-3문장. 무엇을 주장/분석하는 글인지]"
date: "YYYY-MM-DD"
tags: ["적절한태그1", "적절한태그2"] # 3글 이상 모일 구체적 태그만. 범용 "AI" 태그 금지
category: "ai-news" # ai-news | by-tom
subcategory: "column" # 칼럼/분석=column, 단순소식=news, 릴리스=releases
source: "anthropic" # 트리거 출처(anthropic|openai|google|xai|deepseek|kimi|glm|geeknews|github), 자체기획=original
sourceUrl: "https://..." # 트리거 출처 URL (자체기획이면 빈 값)
thumbnail: "/thumbnails/{slug}.png" # 생성 실패 시 생략
draft: false
---

[첫 문단부터 내 주장/질문을 던진다. 고정 인사말 없이, 출처 소개가 아니라
"X는 사실 Y인 것 같아요" / "왜 지금 모두 Z로 가는 걸까요?" 같은 훅으로 시작.
도입 방식은 글마다 달라야 한다.]

## 위키 업데이트 규칙

- 위키 페이지는 `content/wiki/` 디렉토리에 위치
- 엔티티 페이지 (`entities/`): 기업, 제품, 서비스별 페이지
- 토픽 페이지 (`topics/`): 기술 트렌드, 개념별 페이지
- 새 포스트 발행 시 반드시 관련 위키 페이지를 업데이트할 것
- 위키 내용은 블로그에서 실제 다룬 내용만 기록 (추측/외부 정보 X)
- 교차참조: 관련 엔티티/토픽 간 `[[링크]]` 유지
```
