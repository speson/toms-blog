# /write

자체 콘텐츠 발행 커맨드. 주제를 입력하면 리서치 → 작성 → MDX 생성. 주제 없이 실행하면 추천 모드.

## 사용법

```
/write                                              # 추천 모드: 기존 포스트 분석 → 주제 추천
/write AI 코딩 도구 비교: Cursor vs Claude Code      # 직접 주제 지정
/write --category=guide Next.js 15 마이그레이션 가이드
/write --draft AI 에이전트의 미래
```

## 옵션

| 옵션                  | 설명                                |
| --------------------- | ----------------------------------- |
| `--category=opinion`  | 카테고리 지정 (기본: opinion)       |
| `--category=analysis` | 심층 분석 카테고리                  |
| `--category=guide`    | 가이드/튜토리얼 카테고리            |
| `--draft`             | draft: true로 저장 (비공개)         |
| `--no-research`       | 웹 리서치 건너뛰기 (이미 아는 주제) |

---

## 모드 A: 추천 모드 (`/write` — 주제 없이 실행)

주제를 입력하지 않으면 기존 포스트를 분석하여 자체 콘텐츠 주제를 추천한다.

### 분석 방법

`content/posts/` 디렉토리의 모든 MDX 파일을 읽어 다음을 파악:

- 각 포스트의 title, category, tags, source, date
- 최근 뉴스 포스트의 주제 분포
- 기존 자체 콘텐츠(source: "original")의 주제

### 추천 기준 (4가지)

#### 1. 뉴스 기반 심화

최근 뉴스 포스트 중 깊이 다룰만한 주제를 칼럼/분석으로 확장 추천.

**로직:**

- 최근 2주 내 뉴스 포스트 중 태그 빈도가 높은 주제 추출
- 해당 주제로 기존 opinion/analysis 포스트가 없으면 추천
- 뉴스에서 다룬 사실 → Tom의 해석·판단을 더해 심화 (실제 경험은 있을 때만, 범위를 밝혀서)

**예시:**

```
[뉴스 심화] 추천:

1. "LLM 비밀번호 보안의 허점" → 칼럼 확장
   근거: 2/23 뉴스 (llm-password-weakness) — AI 보안 주제 opinion 없음
   제안: AI가 생성한 코드/비밀번호를 어디까지 신뢰할 수 있는지, 실무 관점 분석

2. "OpenAI Rate Limit 아키텍처" → 분석 확장
   근거: 2/23 뉴스 (openai-beyond-rate-limits) — 시스템 설계 심화 가능
   제안: 대규모 API 서비스의 Rate Limiting 패턴 비교 (OpenAI vs Anthropic vs Google)
```

#### 2. 트렌드 묶음

비슷한 주제의 뉴스가 여러 개 쌓이면 종합 분석 추천.

**로직:**

- tags 기준으로 3개 이상 뉴스가 있는 주제 클러스터 탐지
- 해당 클러스터를 아우르는 종합 포스트가 없으면 추천
- 개별 뉴스를 묶어 큰 그림을 그리는 분석

**예시:**

```
[트렌드 묶음] 추천:

3. "2026년 2월 AI 보안 동향 총정리"
   근거: 보안 관련 뉴스 3건 (dji-robot-vacuum, llm-password, ...)
   제안: AI 시대의 새로운 보안 위협을 유형별로 정리하고 대응책 제시
```

#### 3. 커버리지 갭

블로그에서 아직 다루지 않은 주요 AI 토픽을 웹 트렌드 기반으로 추천.

**로직:**

- 현재 블로그의 tags 전체 목록 추출
- 웹 검색으로 최근 AI/개발 트렌드 키워드 수집
- 블로그에 없는 주요 토픽 식별하여 추천

**예시:**

```
[커버리지 갭] 추천:

4. "AI 에이전트 프레임워크 비교: LangChain vs CrewAI vs AutoGen"
   근거: 에이전트 관련 포스트 0건, 2026년 핵심 트렌드
   제안: 공식 문서·릴리스 노트 기준으로 비교 축을 세운 가이드 (직접 실측했다면 그 범위를 명시)

5. "로컬 LLM 실전 가이드: Ollama + Open WebUI"
   근거: 로컬 LLM 관련 포스트 0건, 개발자 관심 높음
   제안: 설치부터 실무 활용까지 가이드
```

#### 4. 시리즈 연결

기존 자체 콘텐츠의 후속편이나 업데이트 버전 추천.

**로직:**

- source: "original" 포스트 중 작성일이 1개월 이상 지난 것
- 해당 주제에 새로운 발전이 있는지 웹 검색
- 후속편/업데이트가 의미 있으면 추천

**예시:**

```
[시리즈 연결] 추천:

6. "OpenCode 한 달 후기, 그 뒤로 무엇이 달라졌나"
   근거: 1/24 작성 "OpenCode 한 달 사용 후기" → 1개월 경과
   제안: 버전 업데이트·새 기능 정리 (사용 소감은 실제 사용 기록이 있을 때만)
```

### 추천 결과 표시 형식

```
자체 콘텐츠 추천 (기존 포스트 N개 분석)

[뉴스 심화]
  1. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

[트렌드 묶음]
  2. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

[커버리지 갭]
  3. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

[시리즈 연결]
  4. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

번호를 선택하면 바로 작성을 시작합니다.
예: "1번" 또는 "3번을 guide로"
```

사용자가 번호를 선택하면 **모드 B (작성 모드)** 로 진입.

## 모드 B: 작성 모드 (`/write [주제]`)

### 1단계: 주제 분석 및 리서치

1. 사용자가 입력한 주제에서 핵심 키워드 추출
2. 웹 검색으로 최신 정보 수집 (`--no-research` 미지정 시)
   - 관련 기술 동향, 수치, 비교 데이터
   - 공식 문서, 벤치마크, 사례
3. 기존 포스트와 중복 여부 확인 (제목/주제 유사도)

### 2단계: 아웃라인 생성 및 확인

수집된 정보를 바탕으로 글 구조를 생성하여 **사용자에게 표시**:

```
아웃라인:

제목 — [독자가 얻는 것을 보여주는 문장, 핵심 검색어는 앞 30자 안]
0. 도입 3문장 — [무슨 일 / 왜 중요(내 판단) / 독자가 얻는 것]
1. [질문형 H2 1] — [다룰 내용]
2. [질문형 H2 2] — [다룰 내용]
3. [질문형 H2 3] — [다룰 내용]
4. 결론 문단 — [그 글의 언어로, 고정 '총평' 헤딩 금지]
5. 자주 묻는 질문 — [질문 2–4개]

이대로 작성할까요? 수정할 부분이 있으면 말씀해주세요.
```

사용자 승인 또는 수정 요청 대기.

### 3단계: 본문 작성

`.claude/guides/writing-style.md`의 Tom 스타일 가이드를 엄격히 따라 작성. 맨 앞 "0. 독자 우선"(R1–R10 + SEO)을 가장 먼저 적용:

- 고정 인사말 금지. 첫 문단은 도입 3문장: 쉬운 말로 무슨 일 → 왜 중요(내 판단) → 독자가 얻는 것 (R2)
- 문장당 새 정보 1개, ~60자, 숫자 2개 이하, · 나열 3항목 이하 (R3). 용어는 첫 등장에 괄호 풀이 (R4)
- 은유 글당 1개 (R5), 작업실 용어(척추·각도·곁가지·훅·층·칸·옆 메모) 본문 금지 (R6), 내부링크 최대 3개 (R7)
- 해요체 통일, "~로 읽혀요" 1회 이하, 판단은 "저는 ~라고 봐요" (R10)
- 가짜 경험 금지. 의견은 의견으로
- 분량: 질문 하나, 핵심 숫자 5개 이하, H2 3–4개. 숫자가 많으면 표로. guide 카테고리는 목록·표·코드 자유 (R9)
- SEO: H2는 검색하듯 묻는 질문형, 끝에 FAQ. 날짜·가격은 "(2026년 9월 기준)"처럼 기준 시점을 적고 가격은 재확인
- 이모지 절대 금지: 💡 🎯 ⚠️ ✅ ❌ 등 모든 이모지 사용 금지 (본문/헤딩/리스트 전부)
- 팁/주의는 평문으로: "팁:", "주의:", "참고:" 같은 텍스트로 명시
- 볼드 처리: `**text**` 금지, 반드시 `<strong>text</strong>` HTML 태그 사용
- 최소 1500자 이상 (AdSense 기준 충분한 분량)

### 4단계: MDX 파일 생성

`content/posts/YYYY-MM-DD-slug.mdx` 파일 생성:

```mdx
---
title: "독자가 얻는 것을 보여주는 문장형 제목" # 날짜로 시작 금지, 영어 용어 1개 이하, 핵심 검색어 앞 30자 안 (R1)
description: "무엇을 다루고 독자가 무엇을 얻는지 2-3문장" # 실제 경험이 없으면 경험 표현 금지
tldrVerdict: "내 판단 2문장, 150자 이내, 숫자 2개 이하" # description·첫 문단 반복 금지 (R8)
date: "YYYY-MM-DDTHH:MM:SS"
tags: ["태그1", "태그2", "태그3"]
source: "original"
sourceUrl: ""
category: "opinion"
draft: false
---

본문 내용...
```

### 5단계: 완료 안내

```
포스트 생성 완료:

- 파일: content/posts/2026-02-24-ai-coding-tools-comparison.mdx
- 카테고리: 칼럼 (opinion)
- 분량: 약 2,100자

`pnpm dev`로 확인하거나 `/commit --push`로 배포하세요.
```

## Frontmatter 규칙

| 필드      | 값                                         |
| --------- | ------------------------------------------ |
| source    | `"original"` (항상)                        |
| sourceUrl | `""` (자체 콘텐츠이므로 빈 값)             |
| category  | `--category` 옵션 또는 기본값 `"opinion"`  |
| draft     | `--draft` 플래그 시 `true`, 아니면 `false` |
| date      | 현재 날짜/시간 (ISO 8601)                  |
| tags      | 주제에서 자동 추출 (3-5개)                 |
| tldrVerdict | 2문장, 150자 이내, 숫자 2개 이하. description·첫 문단 반복 금지 (R8) |

## 카테고리 가이드

| 카테고리   | 라벨   | 적합한 글                                     |
| ---------- | ------ | --------------------------------------------- |
| `opinion`  | 칼럼   | 트렌드 분석, 개인 의견, 비교 분석, 경험 후기(실제 경험이 있을 때만) |
| `analysis` | 분석   | 기술 딥다이브, 아키텍처 분석, 벤치마크 비교   |
| `guide`    | 가이드 | 설치법, 사용법, 튜토리얼, 마이그레이션 가이드 |

## 글쓰기 체크리스트

작성 완료 후 자동 검증 (`.claude/content-model.md` + `.claude/guides/writing-style.md` 기준):

- [ ] 이 분야를 모르는 개발자가 도입 3문장만 읽고 무슨 글인지 말할 수 있는가? (R2)
- [ ] 소리 내어 읽을 때 숨이 막히는 문장이 없는가? (R3)
- [ ] 제목이 날짜로 시작하지 않는 문장형이고, 핵심 검색어가 앞 30자 안에 있는가? (R1·SEO)
- [ ] 용어 풀이(R4)·은유 1개 이하(R5)·작업실 용어 0(R6)·내부링크 3개 이하(R7)를 지켰는가?
- [ ] tldrVerdict가 2문장·150자·숫자 2개 이하인가? (R8)
- [ ] 글의 핵심이 출처 요약이 아니라 내 주장/관점인가? (가치 테스트 통과)
- [ ] 질문 하나·핵심 숫자 5개 이하·H2 3–4개이고, 메타 "척추" 선언·"남는 문장" 헤딩이 없는가? (R9)
- [ ] 해요체로 통일했고 "~로 읽혀요"는 1회 이하인가? (R10)
- [ ] 이모지가 하나도 없는가? (💡🎯⚠️ 등 전부 금지)
- [ ] 볼드는 전부 `<strong>` 태그인가? (`**` 금지)
- [ ] 출처·근거에 링크를 명시했는가? 날짜·가격에 기준 시점을 적었는가?
- [ ] 일반론 총평·가짜 경험 없이 구체적 판단/takeaway가 있는가?
- [ ] 최소 1500자 이상인가?

## 주의사항

- 기존 포스트와 주제가 겹치면 사용자에게 알림
- 웹 리서치 결과는 참고용이며, Tom의 목소리로 재구성
- AI가 쓴 티가 나는 표현 금지 (사실 나열, 딱딱한 문체)
- 추천 모드에서 웹 검색은 커버리지 갭 분석에만 사용 (나머지는 기존 포스트 기반)
