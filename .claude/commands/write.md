# /write

자체 콘텐츠 발행 커맨드. 주제를 입력하면 리서치 → 작성 → MDX 생성. 주제 없이 실행하면 추천 모드.

## 사용법

```
/write                                              # 추천 모드: 기존 포스트 분석 → 주제 추천
/write AI 코딩 도구 비교: Cursor vs Claude Code      # 직접 주제 지정
/write --category=guide Next.js 15 마이그레이션 가이드
/write --draft AI 에이전트의 미래
```

## 옵션

| 옵션                  | 설명                                |
| --------------------- | ----------------------------------- |
| `--category=opinion`  | 카테고리 지정 (기본: opinion)       |
| `--category=analysis` | 심층 분석 카테고리                  |
| `--category=guide`    | 가이드/튜토리얼 카테고리            |
| `--draft`             | draft: true로 저장 (비공개)         |
| `--no-research`       | 웹 리서치 건너뛰기 (이미 아는 주제) |

---

## 모드 A: 추천 모드 (`/write` — 주제 없이 실행)

주제를 입력하지 않으면 기존 포스트를 분석하여 자체 콘텐츠 주제를 추천한다.

### 분석 방법

`content/posts/` 디렉토리의 모든 MDX 파일을 읽어 다음을 파악:

- 각 포스트의 title, category, tags, source, date
- 최근 뉴스 포스트의 주제 분포
- 기존 자체 콘텐츠(source: "original")의 주제

### 추천 기준 (4가지)

#### 1. 뉴스 기반 심화 🔍

최근 뉴스 포스트 중 깊이 다룰만한 주제를 칼럼/분석으로 확장 추천.

**로직:**

- 최근 2주 내 뉴스 포스트 중 태그 빈도가 높은 주제 추출
- 해당 주제로 기존 opinion/analysis 포스트가 없으면 추천
- 뉴스에서 다룬 사실 → Tom의 의견/경험을 더해 심화

**예시:**

```
🔍 뉴스 심화 추천:

1. "LLM 비밀번호 보안의 허점" → 칼럼 확장
   근거: 2/23 뉴스 (llm-password-weakness) — AI 보안 주제 opinion 없음
   제안: AI가 생성한 코드/비밀번호를 어디까지 신뢰할 수 있는지, 실무 관점 분석

2. "OpenAI Rate Limit 아키텍처" → 분석 확장
   근거: 2/23 뉴스 (openai-beyond-rate-limits) — 시스템 설계 심화 가능
   제안: 대규모 API 서비스의 Rate Limiting 패턴 비교 (OpenAI vs Anthropic vs Google)
```

#### 2. 트렌드 묶음 📊

비슷한 주제의 뉴스가 여러 개 쌓이면 종합 분석 추천.

**로직:**

- tags 기준으로 3개 이상 뉴스가 있는 주제 클러스터 탐지
- 해당 클러스터를 아우르는 종합 포스트가 없으면 추천
- 개별 뉴스를 묶어 큰 그림을 그리는 분석

**예시:**

```
📊 트렌드 묶음 추천:

3. "2026년 2월 AI 보안 동향 총정리"
   근거: 보안 관련 뉴스 3건 (dji-robot-vacuum, llm-password, ...)
   제안: AI 시대의 새로운 보안 위협을 유형별로 정리하고 대응책 제시
```

#### 3. 커버리지 갭 🎯

블로그에서 아직 다루지 않은 주요 AI 토픽을 웹 트렌드 기반으로 추천.

**로직:**

- 현재 블로그의 tags 전체 목록 추출
- 웹 검색으로 최근 AI/개발 트렌드 키워드 수집
- 블로그에 없는 주요 토픽 식별하여 추천

**예시:**

```
🎯 커버리지 갭 추천:

4. "AI 에이전트 프레임워크 비교: LangChain vs CrewAI vs AutoGen"
   근거: 에이전트 관련 포스트 0건, 2026년 핵심 트렌드
   제안: 주요 프레임워크를 직접 써보고 비교하는 실전 후기

5. "로컬 LLM 실전 가이드: Ollama + Open WebUI"
   근거: 로컬 LLM 관련 포스트 0건, 개발자 관심 높음
   제안: 설치부터 실무 활용까지 가이드
```

#### 4. 시리즈 연결 🔗

기존 자체 콘텐츠의 후속편이나 업데이트 버전 추천.

**로직:**

- source: "original" 포스트 중 작성일이 1개월 이상 지난 것
- 해당 주제에 새로운 발전이 있는지 웹 검색
- 후속편/업데이트가 의미 있으면 추천

**예시:**

```
🔗 시리즈 추천:

6. "OpenCode 2개월 후기: 그 후로 뭐가 달라졌나?"
   근거: 1/24 작성 "OpenCode 한 달 사용 후기" → 1개월 경과
   제안: 버전 업데이트, 새 기능, 장기 사용 소감 공유
```

### 추천 결과 표시 형식

```
📋 자체 콘텐츠 추천 (기존 포스트 N개 분석)

🔍 뉴스 심화:
  1. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

📊 트렌드 묶음:
  2. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

🎯 커버리지 갭:
  3. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

🔗 시리즈 연결:
  4. [주제] → [카테고리]
     [근거 한 줄] | [제안 한 줄]

번호를 선택하면 바로 작성을 시작합니다.
예: "1번" 또는 "3번을 guide로"
```

사용자가 번호를 선택하면 **모드 B (작성 모드)** 로 진입.

## 모드 B: 작성 모드 (`/write [주제]`)

### 1단계: 주제 분석 및 리서치

1. 사용자가 입력한 주제에서 핵심 키워드 추출
2. 웹 검색으로 최신 정보 수집 (`--no-research` 미지정 시)
   - 관련 기술 동향, 수치, 비교 데이터
   - 공식 문서, 벤치마크, 사례
3. 기존 포스트와 중복 여부 확인 (제목/주제 유사도)

### 2단계: 아웃라인 생성 및 확인

수집된 정보를 바탕으로 글 구조를 생성하여 **사용자에게 표시**:

```
📝 아웃라인:

1. 인트로 — [hook 한 줄 요약]
2. [섹션 1 제목] — [다룰 내용]
3. [섹션 2 제목] — [다룰 내용]
4. [섹션 3 제목] — [다룰 내용]
5. 총평 — [핵심 메시지]

이대로 작성할까요? 수정할 부분이 있으면 말씀해주세요.
```

사용자 승인 또는 수정 요청 대기.

### 3단계: 본문 작성

`.claude/writing-style.md`의 Tom 스타일 가이드를 엄격히 따라 작성:

- "안녕하세요, Tom입니다." 로 시작
- 대화체 한국어: "~예요/해요", "~더라고요"
- 개인 경험/의견 자연스럽게 녹이기
- 이모지 마커 활용: 💡 팁, 🎯 핵심, ⚠️ 주의
- ⚠️ 볼드 처리: `**text**` 금지, 반드시 `<strong>text</strong>` HTML 태그 사용
- 최소 1500자 이상 (AdSense 기준 충분한 분량)

### 4단계: MDX 파일 생성

`content/posts/YYYY-MM-DD-slug.mdx` 파일 생성:

```mdx
---
title: "제목"
description: "개인적 경험을 담은 2-3문장 설명"
date: "YYYY-MM-DDTHH:MM:SS"
tags: ["태그1", "태그2", "태그3"]
source: "original"
sourceUrl: ""
category: "opinion"
draft: false
---

본문 내용...
```

### 5단계: 완료 안내

```
✅ 포스트 생성 완료:

📄 content/posts/2026-02-24-ai-coding-tools-comparison.mdx
📂 카테고리: 칼럼 (opinion)
📊 분량: 약 2,100자

`pnpm dev`로 확인하거나 `/commit --push`로 배포하세요.
```

## Frontmatter 규칙

| 필드      | 값                                         |
| --------- | ------------------------------------------ |
| source    | `"original"` (항상)                        |
| sourceUrl | `""` (자체 콘텐츠이므로 빈 값)             |
| category  | `--category` 옵션 또는 기본값 `"opinion"`  |
| draft     | `--draft` 플래그 시 `true`, 아니면 `false` |
| date      | 현재 날짜/시간 (ISO 8601)                  |
| tags      | 주제에서 자동 추출 (3-5개)                 |

## 카테고리 가이드

| 카테고리   | 라벨   | 적합한 글                                     |
| ---------- | ------ | --------------------------------------------- |
| `opinion`  | 칼럼   | 트렌드 분석, 개인 의견, 경험 후기, 비교 분석  |
| `analysis` | 분석   | 기술 딥다이브, 아키텍처 분석, 벤치마크 비교   |
| `guide`    | 가이드 | 설치법, 사용법, 튜토리얼, 마이그레이션 가이드 |

## 글쓰기 체크리스트

작성 완료 후 자동 검증:

- [ ] 인트로에 "안녕하세요, Tom입니다." 포함
- [ ] "~입니다"보다 "~예요/해요"가 더 많은가?
- [ ] 개인적 경험/의견이 자연스럽게 녹아있는가?
- [ ] 이모지(💡🎯⚠️)를 활용했는가?
- [ ] 따옴표+볼드는 `"**텍스트**"` 형태인가?
- [ ] 마무리에 독자를 향한 인사/추천이 있는가?
- [ ] 최소 1500자 이상인가?

## 주의사항

- 기존 포스트와 주제가 겹치면 사용자에게 알림
- 웹 리서치 결과는 참고용이며, Tom의 목소리로 재구성
- AI가 쓴 티가 나는 표현 금지 (사실 나열, 딱딱한 문체)
- 추천 모드에서 웹 검색은 커버리지 갭 분석에만 사용 (나머지는 기존 포스트 기반)
