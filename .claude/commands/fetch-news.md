# /fetch-news

AI 뉴스·릴리스를 수집하고, 그 재료를 <strong>글 후보(각도)</strong>로 묶어 제안한다.

## 이 커맨드가 만드는 것

선택 단위는 뉴스 항목이 아니라 <strong>글</strong>이다. 최근 포스트가 그렇듯 한 편의 글은
서로 연결되는 소식 2~4건을 Tom의 주장·질문으로 엮은 창작물이지, 뉴스 1건의 번역·요약이
아니다 (`.claude/content-model.md`). 그래서 이 커맨드는 원자료 목록을 보여 주는 데서 끝나지
않고, 원자료를 묶어 "이런 글을 쓸 수 있다"는 후보를 만들어 뉴스 파일 상단에 적는다.
사용자가 따로 요청하지 않아도 <strong>항상</strong> 이렇게 진행한다.

## 실행 단계

1. `pnpm fetch-news --source=ai --limit=5 --save` 실행
   - 스크립트가 수집 → 기존 포스트 `sourceUrl`과 중복 제거 → `.claude/news/YYYYMMDD_news.md`에
     원자료 목록 저장. `--save`가 없으면 파일이 생성되지 않는다.
   - 정상 소요 시간은 약 3초. 몇 분 이상 걸리면 `ps aux | grep fetch-news`로 이전 실행이
     남아 있는지 확인한다.
2. 2차 중복 확인
   - `sourceUrl`이 달라도 이미 다룬 주제가 섞여 있다. 항목의 핵심 키워드(모델명·버전·고유명사)로
     `content/posts/*.mdx`를 grep해 "이미 다룸 (글 slug)"을 표시한다.
   - 이미 다룬 항목은 새 글의 재료가 아니라 허브 링크(내부링크)로 쓴다.
3. 묶기 (angle-first — 건너뛰지 말 것)
   - 원자료를 주제·주체·시기로 묶고, 묶음마다 content-model의 티어를 적용한다:
     - 대형 단독 사건 → 단독 글 후보 (단, 척추는 "발표 내용"이 아니라 "그래서 왜 중요한가")
     - 서로 연결되는 2~4건 → 칼럼 또는 다이제스트 후보 하나
     - 같은 주제가 누적 → 비교/평가 프레임 후보
     - 사소한 패치·베타·소비자 기능 → 보류 (필요하면 다이제스트의 부재료)
   - 후보마다 한 줄 각도(주장 또는 질문)를 쓴다. 한 줄이 안 나오면 후보가 아니라 보류다.
   - 연결고리를 찾는다: `content/wiki/index.md`와 최근 포스트 제목에서 이 후보가 이어받을
     기존 글을 1개 이상 고른다.
   - 후보의 앵커 기사만 원문을 훑는다 (후보당 1~2건, 배치 전체 최대 5건). 각도를 사실에
     붙이기 위한 최소한이며, 정독은 `/publish`에서 한다. openai.com은 WebFetch가 차단되므로
     RSS 본문 미리보기·2차 보도로 대신한다. GitHub 릴리스는 `gh api repos/{repo}/releases/tags/{tag}`.
   - 사고 구조 힌트: 직전 1~2편의 구조(`.claude/guides/writing-style.md` 3-1)를 확인해 후보
     헤더에 "이번 배치 제외 구조"를 적는다.
   - 후보는 3~6개, 우선순위 순으로 A, B, C…. 재료 없이 각도만 있는 후보는 만들지 않는다.
4. 파일 상단의 `## 글 후보 (각도 제안)` 섹션(스크립트가 비워 둔 자리)을 아래 형식으로 채운다.
5. 사용자에게 후보 목록을 보여 주고 선택을 받는다. 선택되면 해당 후보와 구성 항목을 `[x]`로
   바꾼다. 다음 단계는 `/publish`.

## 옵션 (스크립트)

| 옵션                | 설명                                              |
| ------------------- | ------------------------------------------------- |
| `--source=all`      | 전체 (기본값)                                     |
| `--source=geeknews` | Geeknews만                                        |
| `--source=ai`       | AI 블로그 + GitHub + Hugging Face만               |
| `--limit=N`         | 소스당 N개씩 (기본 10)                            |
| `--no-dedup`        | 중복 제거 비활성화                                |
| `--save`            | `.claude/news/`에 파일 저장 (이 커맨드에서는 필수) |

## 뉴스 파일 형식

```markdown
# AI 뉴스 - YYYY-MM-DD

> 수집 N개, 중복 제거 M개, 최종 K개

## 글 후보 (각도 제안)

> 선택 단위는 글이에요. 후보를 고르면 구성 항목이 자동 체크됩니다.
> 각도는 출발점이라 `/publish`에서 원문을 정독한 뒤 다듬어요.
> 직전 글 구조: 시간순 추적 (8/27) → 이번 배치는 시간순 제외

- [ ] **A. [칼럼]** 한 줄 각도 — 주장 또는 질문
  - 재료: #5 · 허브: [기존 글 제목](/posts/slug)
  - 근거 메모: 앵커 기사에서 확인한 사실 1~3개 (숫자·인용 포함)
  - 확인 필요: /publish에서 반드시 검증할 지점
  - 구조 제안: 단일 질문 파기

- [ ] **B. [다이제스트]** ...

### 보류

- #16, #25, #32 (Google Search 소비자 기능) — 독자층과 거리
- #39 (DeepSeek V4 Flash) — 이미 다룸: 2026-08-03-anthropic-open-weights-answer → 허브 링크로만

---

## 수집 항목 (원자료)

- [ ] **1. [제목]**
  - Source: github | openai | anthropic | google | deepseek | kimi | glm
  - Date: YYYY. M. D.
  - URL: https://...
  - 미리보기...
```

## 후보 라벨

| 라벨           | 모델 (content-model.md) | 언제                                                          |
| -------------- | ----------------------- | ------------------------------------------------------------- |
| `[칼럼]`       | 관점/주장 칼럼          | 대형 단독 사건, 또는 연결되는 2~4건 위에 하나의 주장이 설 때   |
| `[다이제스트]` | 종합 다이제스트         | 릴리스·소식 여러 건을 하나의 흐름으로. 항목은 짧게, 기존 글로 허브 링크 |
| `[비교]`       | 비교/평가 프레임        | 같은 주제가 누적됐고 Tom의 축으로 줄세울 수 있을 때           |
| `[단평]`       | 짧은 단평 (400~600자)   | 숫자 하나를 물고 짧게. 결론이 없어도 됨                       |

## 사용자 안내

후보 목록 표시 후 다음 메시지 출력:

```
글 후보 중 쓸 것을 골라 주세요.
예: "A, C 선택" / "B는 각도를 ~로 바꿔서" / 후보에 없는 항목은 번호로 ("12, 15번으로 새 후보")

선택 후 `/publish`가 각도를 다듬어 발행 계획을 확인받고 글을 씁니다.
```

## 하지 않는 것

- 항목을 1:1로 "번역할 항목"으로 제시하지 않는다.
- 후보 없이 원자료 목록만 보여 주고 끝내지 않는다.
- 후보의 각도를 사실처럼 단정하지 않는다. 확인 안 된 것은 "확인 필요"에 적는다.
